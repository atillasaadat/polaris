**what exists and is verified**; the authoritative spec and the requirements
baseline (`docs/requirements/`) remain the sources of truth. Per-push detail
lives in the merged PR descriptions and the design doc's "Implemented (Push N)"
notes — this tracker stays a rollup so it cannot rot the way a narrative does.

The engaging cycle still **publishes coarse** — `Mekf::initialize` seeds an attitude but no rate, so publishing the filter immediately would inject a one-cycle rate dropout into the GNC product while coarse had a good rate — which also makes promotion symmetric with the one-cycle rule demotion follows. Demotion: `FineModeDemoted` carrying `REFUSAL_STREAK` / `NIS_STREAK` / `COAST` / `FILTER_FAULT` / `COMMANDED`, each an action FDIR treats differently, and taking effect immediately (falling back is never worth delaying); a gate rejection is told apart from a refusal on `Mekf::rejectedCount` rather than the return value, since both return false and mean opposite things. A demotion **drops the filter state** (a solution no longer trusted is not worth resuming) and is at least one cycle from the next promotion attempt, so an oscillating condition shows in the event stream. Because `Mekf::reset` clears the rejection count by contract — a commanded reset being "start over" — the component keeps its own **running total** across demotions, so a `NIS_STREAK` demotion cannot erase the FDIR signal that caused it; only `RESET_ESTIMATOR` clears it. Acquisition/loss edges moved onto the **published** solution, so a demotion with coarse live underneath emits no `AttitudeLost` — nothing was lost. Seven new no-default parameters through the Push 41 `configc`→`ParameterDb` path (19 total), behind a **second, non-fatal validity gate**: a missing coarse value still refuses the estimator, a missing fine value emits `FineConfigInvalid` and leaves a flyable vehicle on the §10 floor. One cross-field gate ties the sets together — `MekfMaxCoastSec ≤ MaxCoastSec`, since the live-fallback premise requires coarse to outlast fine. The MEKF's ARW and max step are the coarse chain's `GyroArw`/`MaxDtSec` — two parameters for one physical quantity is two chances to disagree — and the per-update sigma is each source's white ⊕ systematic parts, since the filter treats `R` as white; that inflation is still optimistic against a sun/mag-only systematic budget, which the §8.2 star-tracker path is what actually fixes. Reference-vehicle values derived from its own hardware: σ_u from the STIM300 0.3 °/hr Allan floor through the Gauss-Markov relation at the modelled 100 s correlation time, χ²₂ at 99.9% for the NIS gate, the 10 °/hr turn-on repeatability for the seed bias sigma, `sin²(θ/2) = 0.0076` at 10° separation for the seed observability gate (the eigenvalue ratio is `(1 − cos θ)/2`, not `sin²θ/2` — they agree only at 90°, and the wrong form gates at ~14°), and a 300 s fine coast horizon against the coarse 2400 s (eclipse alone does not reach it — the magnetic pair still updates the filter in shadow). New telemetry: `MekfNis` (the cycle's **largest**, so a good update cannot hide the outlier before it), `MekfRejected`, `MekfRejectedTotal`, `GyroBias`, `FineAttCovTrace`, `BiasCovTrace`, `FineDemotions`. +6 component tests (15 total): promotion with an injected 0.06 °/s bias converging over 60 s and the fine covariance falling below a third of the seed's (with the engaging cycle pinned to still publish a valid coarse rate), NIS-streak demotion driven by a sun vector 60° off with the magnetic pair kept honest and the running rejection total surviving it, refusal-streak demotion driven by a zero-length but finite sun vector that clears the finiteness gate and is refused as unnormalisable (rejection total stays zero — a refusal is not an outlier), coast demotion with both sources withdrawn, no demotion producing an `AttitudeLost`, coarse-only operation on missing fine tuning, and `RESET_ESTIMATOR` demoting `COMMANDED` then re-seeding. `FILTER_FAULT` stays unexercised in the harness — reaching a non-finite internal result means getting past a finiteness gate in the component *and* in `Mekf::update`, which tests the harness rather than the component. The SITL tuning gate now also asserts 19 records loaded, `FineModeEngaged`, and no demotion over the run |
| 45 | — | Quantitative attitude-knowledge accuracy (§8.1; **REQ-ADET-005/006/007**), stated on the **error norm** — the total eigenaxis angle `θ_err = 2·arccos|q_err,0|` at the 3σ (99.73rd-percentile) point — rather than a per-axis split, because the norm is rotation-invariant and is what a pointing budget consumes directly; a boresight/cross-boresight split waits for a payload that distinguishes the body axes. `tests/unit/attitude_accuracy_mc_test.cpp` is the verifying campaign and the CI enforcement: 800 runs on the reference vehicle's own budget, one shared draw per run feeding both estimators, with **systematics drawn once per run as biases and white terms per measurement** (modelling the systematic part as white would make the campaign vacuously easy — the reported error would fall as 1/√N instead of settling on the floor the hardware has), sun/field geometry swept over the well-conditioned band, and the sample **maximum** asserted as a distribution-free 88%-confidence upper bound on the 99.73rd percentile rather than a raw empirical quantile. Each test also asserts a **sensitivity floor** on the median, so a bug that zeroed the noise fails instead of passing silently. The thresholds were **set from the measurement, not the other way round**: coarse 3σ = 8.5°, fine 3σ = 8.1° on the same SS+MAG+IMU suite, both against a 15° requirement (43% / 46% margin), under the stated condition that the sun and field are ≥ 45° apart. Two results are worth reading twice — the **coarse and fine thresholds are equal**, because with only two vector sources neither a fixed-gain blend nor an optimal filter can separate a constant offset from the truth, so both land on the same systematic floor (the §8.1 caveat, quantified: 8.1° against 8.5° is better by 0.4° on a floor of 8°); and the **tail is the Rayleigh tail of the systematic draw**, not a filter pathology — instrumenting the worst runs shows zero NIS rejections and no coasting. The filter is nonetheless the better of the two **run for run**, and the campaign is built to settle that honestly: **one draw — geometry, truth motion, systematic biases, every noise sequence — feeds both estimators**, so the comparison is paired rather than two samples of the same budget. Paired, the MEKF wins **65% of the 800 runs** with a median per-run improvement of 0.20°, against the 50 ± 1.8% a coin flip would give, and the win fraction holds between 64.2% and 65.4% across every seed tried. Sharing the draw also halves the work, since the payload requirement reads the same fine-mode results instead of re-running the campaign. Improving these is a sensor-budget action (hard-iron calibration, albedo correction, a tracker), not an estimator-tuning one. REQ-ADET-007 (star tracker, ≤ 0.05°) is held at `reviewed` with no verifier — the status the traceability gate does not act on — and is set at 0.05° rather than the ~0.02° a datasheet skim suggests because on the *norm* metric a single AURIGA is dominated by its about-boresight axis (~95 arcsec 3σ RSS against ~16 cross-boresight, plus the unit's fixed 61 arcsec `bias_deg` — not the separately configured thermo-elastic drift — which does not average down at all); two trackers with non-parallel boresights are what buy the 0.02°-class figure. **Stage 2** adds the generic **payload sensor** (§6.3) that makes the axis-resolved form measurable: any instrument with a boresight — imager, laser, rangefinder — modelled as pointing geometry only, with **+Z the boresight always** (not configurable, because a boresight vector on top of a mounting rotation is two ways to express one orientation and the failure is silent), conic/square/rectangular fields **inferred from which half-angles the catalog entry sets** rather than named by a key that could contradict them, pixel format and IFOV, and the **shared §6.1 occlusion evaluator** — non-circular fields passed as their equal-solid-angle equivalent cone, the same order of approximation the coverage fractions already carry, with an exact per-direction shape test alongside. ## Build & verify locally

Dependencies are managed with [uv](https://docs.astral.sh/uv/); `uv sync`
creates `.venv`, provisions Python 3.12, and installs the pinned toolchain
(`cmake`/`ninja` as wheels). Only `doxygen` is a system package.

```bash
# One-time
uv sync                             # F´ toolchain + dev tools (from uv.lock)

# F´ flight build
uv run fprime-util generate && uv run fprime-util build

# FSW tuning: compile the vehicle config into a Svc::PrmDb parameter file and
# run the deployment against it (the flight build must exist first — the
# parameter IDs come from the generated topology dictionary)
PYTHONPATH=tools uv run python -m configc \
    --config config/spacecraft/leo_smallsat.yaml --hardware config/hardware \
    --dictionary build-artifacts/Linux/flight_PolarisFsw/dict/PolarisFswTopologyDictionary.json \
    --out build/config
./build-artifacts/Linux/flight_PolarisFsw/bin/flight_PolarisFsw -P build/config/PrmDb.dat -s 50051

# C++ test suites (unit runs under ASan/UBSan)
uv run cmake --build build-fprime-automatic-native-ut \
    --target polaris_unit_tests polaris_integration_tests polaris_golden_tests -j4
./build-fprime-automatic-native-ut/bin/Linux/polaris_unit_tests
./build-fprime-automatic-native-ut/bin/Linux/polaris_integration_tests
./build-fprime-automatic-native-ut/bin/Linux/polaris_golden_tests

# Python suites (config compiler, GMAT harness, space weather, orbit)
uv run pytest tests/tools

# Docs site (warnings are errors; same gate as CI)
sudo apt-get install -y doxygen     # one-time
uv run --only-group docs bash tools/dev/build_docs.sh   # -> docs/_build/html/index.html

# Lint (CI runs exactly this; the pre-commit git hook runs it per-commit)
uv run --only-group dev pre-commit run --all-files
```
