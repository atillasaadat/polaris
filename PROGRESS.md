phasing (`docs/design/Polaris_Design_Document.md` §24). This file summarizes
**what exists and is verified**; the authoritative spec and the requirements
baseline (`docs/requirements/`) remain the sources of truth. Per-push detail
lives in the merged PR descriptions and the design doc's "Implemented (Push N)"
notes — this tracker stays a rollup so it cannot rot the way a narrative does.

Measured against a truth atmosphere 60 % denser: after six orbits at the flown tuning the estimate is **1.023 of a true 1.6** (4 % of the error) with sigma still 0.33 of its 0.5 prior; **arc length is not the lever** (one orbit gives 1.006), `q_a` is — at `q_a`/1000 the same filter reaches **1.516 with sigma 0.158 in a single orbit**. And `q_a` cannot be reduced: Push 74 measured every reduced-`q_a` variant failing the NEES consistency gate, precisely because `q_a` covers that truncation. The two are locked, so **what unblocks this on the reference vehicle is a higher-degree onboard geopotential, not a longer pass** — a degree-20-plus field against the 8x8 flown. Same shape of result as the tier-3 *dipole* estimator's 40x-under-the-noise-floor verdict, and handled the same way: shipped tested, parameterised and telemetered, disabled on this vehicle, with the sigma that makes its own limit legible at runtime. The flown trajectory is asserted **bit-for-bit unchanged** with the state off, so nothing about the current tuning moved. **SRP scale factor deliberately not built**: the onboard force model carries no SRP term at all, so it would mean adding a term an order below the drag it would sit beside on a 400 km vehicle — deferred with its number rather than built speculatively. Thrust scale factor stays with the burn work. **No FreeFlyer row, and the exemption is quantified rather than asserted** (`CLAUDE.md`): at the flown tuning the state changes the propagated position by **4.5 cm over a full 1800 s degraded coast** — 2.3 % of a 1.2e-6 m/s² term — which has no orbit signature a viewer can show against a 6800 km radius. Tests: +10 library cases (the exact Jacobian against both a differenced column and the term's linearity; recovery of a known bias with the truncation budget out of the way; the flown tuning's non-resolution as an **asserted upper bound**, so the day the onboard field improves this fails and says why; the short-arc sigma; refused-not-clamped; enable-by-uplink re-seeding; and the configuration refusals) plus a component case covering the parameter path and the three channels. |

## Build & verify locally

Dependencies are managed with [uv](https://docs.astral.sh/uv/); `uv sync`
creates `.venv`, provisions Python 3.12, and installs the pinned toolchain
(`cmake`/`ninja` as wheels). Only `doxygen` is a system package.

```bash
# One-time
uv sync                             # F´ toolchain + dev tools (from uv.lock)

# F´ flight build
uv run fprime-util generate && uv run fprime-util build

# FSW tuning: compile the vehicle config into a Svc::PrmDb parameter file and
# run the deployment against it (the flight build must exist first — the
# parameter IDs come from the generated topology dictionary)
PYTHONPATH=tools uv run python -m configc \
    --config config/spacecraft/leo_smallsat.yaml --hardware config/hardware \
    --dictionary build-artifacts/Linux/flight_PolarisFsw/dict/PolarisFswTopologyDictionary.json \
    --out build/config
./build-artifacts/Linux/flight_PolarisFsw/bin/flight_PolarisFsw -P build/config/PrmDb.dat -s 50051

# C++ test suites (unit runs under ASan/UBSan).
# Generate the UT tree ONCE with -O2 (asserts stay live — the Debug type only
# appends -g, no NDEBUG): unoptimized Eigen makes the SITL rows ~30x slower,
# which is hours of ctest. Omit the flags only when single-stepping a test.
#   uv run fprime-util generate --ut -DCMAKE_CXX_FLAGS=-O2 -DCMAKE_Fortran_FLAGS=-O2
uv run cmake --build build-fprime-automatic-native-ut \
    --target polaris_unit_tests polaris_integration_tests polaris_golden_tests -j4
./build-fprime-automatic-native-ut/bin/Linux/polaris_unit_tests
./build-fprime-automatic-native-ut/bin/Linux/polaris_integration_tests
./build-fprime-automatic-native-ut/bin/Linux/polaris_golden_tests

# Python suites. `--group analysis` pulls numpy/scipy/matplotlib for the
# tests/analysis/ linear control-analysis suite (REQ-ACTL-006/007/008); without
# it those cases fail to import rather than skipping, which is deliberate.
uv run --group analysis pytest
uv run pytest tests/tools                # config compiler, GMAT harness, space weather, orbit

# Docs site (warnings are errors; same gate as CI)
sudo apt-get install -y doxygen     # one-time
uv run --only-group docs bash tools/dev/build_docs.sh   # -> docs/_build/html/index.html

# Lint (CI runs exactly this; the pre-commit git hook runs it per-commit)
uv run --only-group dev pre-commit run --all-files
```
