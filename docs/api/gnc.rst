GNC — ``polaris::gnc``
======================

Estimation, guidance, and control algorithms shared by the FSW and the analysis side (design doc §8). Phase 4 starts with the **coarse attitude chain**: the deterministic **TRIAD** single-frame initializer and the **SS+MAG+IMU coarse estimator** that stands behind the Safe-mode floor (§8.1, §10) — star-tracker- and table-independent, since the analytic Sun ephemeris (§11.3) always answers. The **fine mode** sits alongside it: **Davenport's q-method** for an optimal attitude from any number of weighted vector pairs (cold start and re-init only), and the 6-state **MEKF** estimating attitude error and gyro bias with per-update NIS gating and NEES/NIS consistency diagnostics. Alongside the estimators sits the first of the §8.1 **on-orbit calibrations**: an attitude-free magnetometer hard/soft-iron fit, a streaming ten-parameter ellipsoid least-squares against the onboard IGRF field *magnitude*, which needs no attitude solution and so runs from Safe mode on an uncalibrated vehicle. Beside it sits the second item of the same roadmap, the **Earth-albedo correction** of the sun vector — a *model* rather than a commanded calibration, since it needs geometry and not collected data, so it runs on every cycle whose geometry supports it and refuses (leaving the measurement untouched) on every cycle it does not. Phase 5 adds the **control** half (§8.5): the **B-dot** detumble law in its field-strength-normalised form, with the field derivative formed from successive quiet-window magnetometer samples and their own time tags and the demand divided by the §7 duty factor; the **quaternion-error PID**, taking the short way round and with an integrator that is both clamped and frozen while the torque saturates; and the **reaction-wheel allocation**, L2 by pseudo-inverse and exact L-∞ over a four-wheel array's one-dimensional null space, with saturation scaling the whole vector so the commanded torque direction survives it. Pure math on the canonical ``EstimatedState``: no F´ types and no I/O, so the F´ ``AttitudeEstimator`` and ``AttitudeController`` components are thin wrappers.
